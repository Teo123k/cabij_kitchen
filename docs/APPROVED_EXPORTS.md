# Approved export source

The delivery screen selects the stored package snapshot for the current saved project revision. Print, recipe PDF, SpreadsheetML, JSON and Slack preview read that same snapshot. Artifacts include the package ID, revision, calculation-run ID and engine version; draft and synthetic output are labelled. Approved spreadsheets use stored values rather than editable formulas. Export and sharing are blocked when a selected package is stale, belongs to another kitchen or has no calculation-run reference. Historical packages without a run remain in history but must be recalculated and approved before delivery. The local Slack bridge checks the signed-in manager's membership, reloads the package and checks the current project revision before sending.

This is a local integration, not production acceptance. The worker that creates calculation runs still uses the JavaScript reference; Python arithmetic and scheduling remain shadow-only. Client-side exports are not signed documents and their labels are not proof of authorization or authenticity. The local Slack bridge and its delivery journal are not a durable multi-worker service. Staging migrations, authenticated browser tests, export reconciliation with real source documents, Slack delivery confirmation, task completion sync, production authentication and operational review remain required. No hosted service is changed by these files.
